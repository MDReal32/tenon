# Decisions

This page records the design questions that are settled, each with its decision. A role or session treats them as settled and changes one only when the owner asks.

| #   | Topic                        | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Canonical schema             | **JSON Schema.** WIT is a separate binding for the WASM transport.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 2   | Conditions                   | **Structured conditions, written natively in each SDK.** Options and decisions carry tags for the common case, and a `when` condition for the rest, built with the SDK's matchers (in TypeScript: `when: { lang: { primary: "rust" }, x: not(y), d: notIn([]) }`). It reaches the engine as structured data over the protocol, and the engine evaluates it; there is no string expression grammar.                                                                                                                                                                                                                                                                          |
| 3   | Operation kinds              | **No privileged built-in operations beyond a tiny primitive kernel.** The engine only knows primitives that need host privilege: VFS `write`/`delete`/`mkdir`, `exec`, `message`. Everything else (`render`, `copy`, `merge-*`, `patch`, …) is an operation kind provided by an extension (first-party: `tenon.std-ops`, bundled but loaded like any other) and **lowers to primitives**. A handler is pure: (operation, state, read-only VFS snapshot) → primitives. The plan preview is the fully lowered primitive list. Same rule applies to Base: it gets nothing community extensions can't get. Ordering/conflict rules for handlers to be specified before M1 ends. |
| 4   | Extension-to-extension calls | **Facts only** initially. Typed, manifest-declared *services* may be added later if real use demands them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 5   | Interpreters                 | **System tools.** Process extensions run on the interpreters already on the user's `PATH` (Node, Python, …), with a clear, actionable error when one is missing. Tenon doesn't download or manage interpreters. WASM remains the zero-dependency path.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 6   | Registry                     | **Each language's own package manager.** Plugins are published to crates.io, NuGet, npm and the like, and Tenon installs from those, from git or from a local path. A website later gathers them with install instructions, and Tenon's CI-side validation checks a plugin when it is published. No registry server of Tenon's own.                                                                                                                                                                                                                                                                                                                                         |
| 7   | `exec` operations            | **Runs without a prompt, allow-listed per extension, shown in the output and in `--dry-run`.** Running `tenon new` is the user's consent. Recorded in `tenon.lock` once the lockfile exists, in a later milestone.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

The last page, [still open](03-still-open.md), lists what isn't settled yet.
